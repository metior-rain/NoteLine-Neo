# NoteLine 谱面制作

交付可直接导入 NoteLine 的 `.nlchart`，其中包含原音频、可用封面和用户需要的难度。沿用本项目约定：未指定难度时制作简单、普通、困难三套独立编排；用户指定的难度、风格和密度优先。

## 使用环境

先定位当前 NoteLine 项目，检查 `src/score-package.js`、`src/chart-format.js`、`src/difficulties.js`、`src/path-notes.js` 和 `src/engine.js`。本技能的打包脚本调用项目现有实现，避免另造不兼容格式；用 `--repo` 指定项目根目录。在本机，该项目通常位于 `/Users/mizuyomi/Documents/ChatGPT/Noteline`，但不要假定其他环境路径相同。

音乐分析使用 ffmpeg、ffprobe、Python 和 NumPy，打包使用支持 Blob 的 Node.js（20+）。优先用已有运行环境；桌面提供 `load_workspace_dependencies` 时可查找附带 Python。不要为缺少 NumPy而修改全局 Python。脚本的 `--help` 说明参数。

## 音乐分析与对齐

1. 读取用户明确指定的本地音频，在项目 `exports/<曲名>/` 写交付文件。音乐和原有谱面都不就地覆盖；修改已有谱面时另存版本。
2. 用 `scripts/analyze_audio.py AUDIO --out-dir ANALYSIS_DIR` 获取解码时长、节拍候选、八分拍相位、分段能量、瞬态和嵌入封面。该工具不产生最终谱面，也不识别人声旋律。
3. BPM 候选需要交叉判断：自相关容易得到半拍、倍拍或三连音速度。比较开头、中段、结尾的拍点是否持续对齐，再选 BPM。**八分拍相位不能直接当成小节首拍**；还要确认强拍、弱起和小节位置。
4. 明确 `beatOffset`（首拍网格起点，毫秒），即使它恰好为 0 也须有证据。音符时间始终相对解码后的音频零点，首拍偏移不会自动移动音符。不要把 3 秒倒计时写进音符时间，也不要裁掉音乐开头。
5. 通过局部波形、频带瞬态、段落能量，以及可用的试听方式检查节拍。仅做了信号分析时如实说明依据，不声称已经听过或人工试玩过。若有变速、自由节奏或显著局部偏离，按实际时间安排音符，不强行把全曲吸附到恒定网格。

## 编排

制作前读 [references/charting.md](references/charting.md)，它包含难度、手型、长按与本游戏判定的实际约束。

- 先标记乐句和强弱段，再选择要表现的音乐层：鼓点、钢琴、伴奏或旋律。保留停顿，重复乐句使用可辨认的主题和呼应变化。
- 简单突出主拍与显著旋律；普通加入切分、短连打及适量双押；困难叠加节奏层、交替连打和长按配合。不要用随机轨道或固定删去一半音符来冒充独立难度。
- 同时击打的音符使用完全相同的时间戳；不要靠几毫秒错开来绕过双押。长按对应持续的音乐，不仅为了凑数量。
- 支持单击、长按、流星、弹跳四种音符。流星是在轨道上保持、在节点前短暂变轨的持续音符；弹跳先从轨道下落，再逐落点点击。需要编排路径时读 [references/format.md](references/format.md) 的路径示例及 [references/charting.md](references/charting.md) 的占用约束，不把路径音符当成普通长按。按音乐与玩家水平使用，不强制每档都加入新类型。
- 注意左右手、重复指负担、长按占用和段落密度。统计每秒峰值、同轨最短间隔、最大实际同时占用按键数，按用户水平调整；不是音符越多越好。
- 把编排写成 `{ "charts": { "easy": {...}, "normal": {...}, "hard": {...} } }` 源谱 JSON，使用毫秒。精确字段见 [references/format.md](references/format.md)。不要输出旧版 JavaScript 乐谱。

## 打包与验证

使用本技能 `scripts/package_chart.mjs`，而不是手工拼接二进制：

```sh
node SKILL_DIR/scripts/package_chart.mjs \
  --repo PROJECT_DIR --charts SOURCE_JSON --audio AUDIO_FILE \
  --cover COVER_FILE --out OUTPUT_NLCHART --report REPORT_JSON
```

没有封面时省略 `--cover`；只制作指定难度时增加 `--difficulties normal` 或相应逗号列表。上述大写路径是需要替换的参数，不要照抄为文件名。

脚本检查真实解码时长、音符结构与边界，使用当前游戏引擎模拟精确按下/释放、流星持续跟随及弹跳各次落点，重新读取成品，校验全部难度以及原音频/封面 SHA-256。它区分谱面对象数与实际判定数，输出四种音符组成、双押、判定峰值密度、手指占用和同轨间隔。**模拟全连只证明判定和结构可用，不证明音乐性、键盘换键或真实触控手感已经合格**，仍需检查明显的段落错位和不合理手型。不要为了通过验证静默删除失败音符。

如果只是编谱，不修改游戏逻辑，不自动写入浏览器曲库或覆盖用户草稿。用户要求导入/试听时才操作对应界面。只为出谱不需启动或改造服务。

## 交付

给出 `.nlchart` 的绝对路径链接，简洁列出各难度的音符对象数、实际判定数及长按/流星/弹跳数，说明文件包含音频，以及是否包含封面。有路径时 Combo 总数按实际判定数报告。保留源谱和统计报告方便返修。核实数量与成品一致。不要将 NumPy 缓存、临时 PCM 或分析图当作主要交付，也不要分享/上传音乐到外部服务。
